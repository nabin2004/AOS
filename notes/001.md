One thing I think you're missing completely
Cognitive Load

Grant isn't just making pretty animations.

He's carefully controlling how much new information appears at once.

Your storyboard should have rules like:

max_new_objects_per_beat: 3

max_new_equations: 1

max_new_colors: 2

max_narration_seconds: 20

max_simultaneous_motion: 2

Those aren't renderer constraints.

They're learning constraints.

A planner that respects them will usually produce clearer educational videos than one that simply maximizes visual complexity.

Overall assessment

If I had to score this as a first architectural draft, I'd give it 8/10.

The strongest ideas are:

Thinking in lectures rather than code.
Focusing on entities and state changes.
Recognizing that pauses still need subtle motion.
Planning reusable educational assets instead of one-off animations.

The main thing I'd change is to make the abstraction layers much cleaner. Right now Lecture, Storyboard, Scene, Entity, Beat, and Action overlap in responsibility. If each layer answers exactly one question—for example, Lecture = what to teach, Storyboard = teaching strategy, Scene = visual arrangement, Beat = state transition, Compiler = Manim code—the whole system will be easier to reason about, extend, and train a model against. I think getting those boundaries right is more important than adding more classes at this stage.
